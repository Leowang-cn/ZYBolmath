# 实验分支：仅浏览器导出容器化

## 重新扫码登录

管理员在更新弹窗点击“重新扫码登录”会创建同步任务，在取得同步锁后选择新的专用浏览器会话，并访问钉钉登录入口。扫码完成后继续导出；后续普通同步复用所选会话。任务运行期间按钮禁用，后端也拒绝重复任务。

会话选择保存在任务数据库旁的 `dingtalk-session` 文件，浏览器数据位于原 profile 父目录下的 `dingtalk-session-<任务ID>`。旧会话不再使用，但保留在磁盘上；其中可能包含登录凭据，由管理员在确认无运行任务后清理。题库数据不受影响。登录未完成时仍保留新会话选择，可再次重新扫码登录。

真实登录入口和扫码识别仍需服务器验收；“未找到导出菜单/选项”不代表已确认账号无权限，只有页面明确提示禁止导出时才使用权限拒绝错误。

Flask、SQLite、XLSX 解析、打包和题库安装仍在宿主机运行。仅 Playwright 和 Chromium 在预先构建的 `olmath-chromium-runner:1.55.0` 中执行，不要求升级宿主机 glibc，也不要求宿主机安装 Chromium。

## 配置

在 staging 的环境文件增加：

```sh
DINGTALK_EXPORT_BACKEND=container
DINGTALK_RUNNER_IMAGE=olmath-chromium-runner:1.55.0
DINGTALK_RUNNER_TIMEOUT_MS=900000
SYNC_JOB_TIMEOUT_SECONDS=1800
BROWSER_PROFILE_PATH=/data/deploys/olmath-staging/data/browser-profile
```

沿用已配置且用引号包围的 `DINGTALK_DOCUMENT_URL`、`EDITOR_PASSWORD`、`SECRET_KEY`，以及 `ASSET_BACKEND=local`。默认导出后端仍为 `local`，需显式开启容器模式。沿用现有 Gunicorn 启动方式。

## 上线前提

- 使用本机 Docker daemon；远程 Docker 无法直接访问宿主机临时目录。运行账号必须能够执行 Docker，Docker 权限具有较高宿主机权限，应由管理员授权。
- 镜像必须已存在于服务器。镜像需提供 Python 3、Playwright 1.55.0、`/usr/bin/chromium` 和 UID 1000 的 runner 用户。
- 宿主机任务进程须为 root 或 UID 1000。profile 和临时工作目录使用 UID 1000、权限 0700；不满足条件会明确报错，不会放宽到 0777。root 启动时仅调整这两个目录的所有者，不递归改动已有文件。
- 已有 profile 内部文件也应归 UID 1000；管理员应在停止同步时检查。代码目录需要允许容器用户遍历和读取，尤其是 `scripts/container_export.py` 与 `scripts/dingtalk_export.py`。
- scripts 只读挂载；临时工作目录、独立 browser profile 可写挂载。不得使用生产 profile 或数据目录。
- 默认容器总时限 15 分钟；若修改浏览器登录/导出时限，应一并调整总时限，并使任务过期时限更长。

## 日志和清理

每个任务的宿主机输出保存在任务数据库旁的 `sync-logs/<任务ID>.log`，新目录 0700、新文件 0600。正常容器退出后记录末尾最多 8 KiB 输出，过滤 URL 和常见凭据字段；这不是完备的秘密识别器，日志仍须限制访问。日志不通过 API 公开，由管理员定期清理。超时退出可能没有浏览器日志尾部。

容器名为 `olmath-export-<随机ID>`，正常结束、超时、回调失败时均尝试强制移除容器，再清理宿主机工作目录。若 Docker 无响应，记录容器名供管理员清理；宿主机进程被 SIGKILL 或服务器重启时，不能保证执行 finally 清理。上线检查应包括遗留容器、临时目录及登录凭据管理。

状态查询会将长时间未更新的任务标为 `worker_timeout`，允许界面重试。这是状态恢复，不是进程终止机制；原工作进程仍受既有同步文件锁保护。

## 验收边界

本实现复用现有“菜单 → 导出 Excel → 浏览器下载事件”流程，并校验 XLSX 内容。若钉钉改为“后台生成，通知中下载”，当前实现会超时，不会把通知页面当作成功结果。该流程必须在真实目标文档和授权账号下验证后才能宣称可用。

服务器验收：启动同步 → 扫码 → 下载 XLSX → 解析及安装成功；再次同步验证登录持久化；再测拒绝访问、登录超时、容器启动失败，确认任务错误、日志及容器清理。不要在生产环境做这些故障测试。
